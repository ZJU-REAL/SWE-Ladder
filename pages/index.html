// the idea

Show the teacher only what each stage needs, and teach the stages in repair order.

teacher_evidence.diffOPSD → SWE-Ladder

-Teacher sees the full reference patch at every step: the same evidence at every stage.

+LOC steps get the changed files and line ranges.

+REP steps get the fail-to-pass tests.

+PATCH steps get the reference diff, one stage at a time, in that order.

Reinforcement learning with verifiable rewards gives one signal for the final patch. On-policy self-distillation (OPSD) adds dense token-level guidance, but a teacher shown the full reference patch at every step gives the same evidence at every stage. SWE-Ladder turns each verified repair into three stage-specific evidence views and distills them one stage at a time, training a single end-to-end agent that sees no privileged evidence at inference time.

rung 01 · method

Three evidence views, one router, one stage at a time.

Stage-specific evidence

The verified repair and its tests are converted into three evidence views. The student never sees any of them. All teacher variants share the student's system and task instructions; only the appended evidence block differs.

stagerouter seesteacher evidencedistilled tokens
LOC Search, file view, read-only shell Changed non-test files, old-side hunk ranges, and pre-patch source lines Response tokens labeled LOC during the LOC phase
REP Repro script creation/execution, test file edits, test runs Fail-to-pass test identifiers/names, reference test code, and candidate test changes Response tokens labeled REP during the REP phase
PATCH Source-file edits The verified repair diff Response tokens labeled PATCH during the PATCH phase

# Stage labels are annotations for distillation only. They do not constrain tool choices, truncate rollouts, or change the reward.

Progressive schedule

Each phase resumes the previous checkpoint.

  1. 3patch_generation20 iterationsglobal_step_70
  2. 2localized_issue_reproduction20 iterationsglobal_step_50
  3. 1causal_localization30 iterationsglobal_step_30

The 70-iteration total matches the GRPO control: both runs take the same 70 policy updates on the same data and differ only in where privilege is applied.

The stage router

The router is a deterministic tool-level state machine. It consumes only the parsed tool call and advances forward in repair order, with state-dependent backtracking.

  • REP → LOC after three consecutive exploration actions.
  • PATCH → REP after one test run.
  • PATCH → LOC after one exploration action.
  • LOC → PATCH on a patch proposal, skipping REP.

rung 02 · results

Higher pass@1, shorter trajectories, and agents that finish on their own.

All methods start from Qwen3-4B-Instruct-2507 and are evaluated on the 500 instances of SWE-bench Verified without task-specific supervised fine-tuning before RL. GRPO+OPSD shows the teacher the full reference patch at every step; SDAR is a gated OPSD method for agents, given the same patch evidence.

rung 03 · analysis

The privileges are not interchangeable.

A causal probe restores real environments from base-model trajectories, adds one kind of privilege, and executes the candidate next actions in containers. Each privilege helps most in its own stage.

top of the ladder · takeaways

Don’t show the teacher the whole answer at every step. Give localization, reproduction, and patching each its own evidence, in the order a repair happens.

git log --reverse takeaways
  1. #01

    Stage-specific privilege beats whole-answer privilege.

    A teacher shown the full reference patch at every step gives every stage the same evidence. Routing the evidence by stage does better.

    12.4% → 16.4%GRPO+OPSD (full patch) vs. SWE-Ladder, R2E-Gym pass@1

  2. #02

    Order matters.

    Teaching the stages all at once, in reverse, or reproduction first all fall short of repair order.

    11.4–12.6%other schedules vs. 16.4% in repair order

  3. #03

    Every stage contributes.

    Removing any one stage of privileged supervision lowers pass@1.

    11.2 / 13.2 / 14.0without LOC / REP / PATCH

  4. #04

    A simple router trains a better agent.

    A neural router matches annotator labels more often but yields lower downstream pass@1.

    92.0% vs. 98.63%rule-based vs. neural agreement

  5. #05

    Shorter rollouts that end on their own.

    No teacher, no stage labels, and no fixed pipeline at test time: one end-to-end policy.

    19.3 steps · 98.6%avg. steps and env_done on R2E-Gym
